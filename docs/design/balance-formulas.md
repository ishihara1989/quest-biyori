# 多ステージ共通のバランス計算案

2026-10-10 JST。以下の成長・装備・ダメージ・スキルの式は初期値を決める提案で、本編には未適用。その後の追加指示で、森3と各地域の1・5以外の敵HP・火力・編成を先に調整した。[本編へ適用した内容](../history/stage-balance-adjustment.md) と [30配置の検証結果](../../output/balance/stage-tuning-verification.md) を参照。

2026-10-09の [既存方針](../policies/balance-policy.md) の経験値、素材確率、装備費用、取得数ボーナス、周回を維持する。今回の攻略基準は「当該ステージまでのメインのみ、適正レベル、解放順のアクティブ」で評価し、枝やジェムを必須にしない。

## 1. 基準ビルドを固定する

通算ステージを `s` とする。森1〜10が1〜10、沼地1〜10が11〜20、洞窟が21〜30、海岸が31〜40。

| 要素 | 攻略基準 |
| --- | --- |
| レベル | 全員Lv.s。過剰レベルによる力押しを入れない |
| 仲間 | 挑戦開始時に加入済みのキャラ。森5から魔法使い、沼地1からパラディン |
| アクティブ | 解放レベルの低い順に、各最大ランクまでSPを割り振る |
| 通常攻撃 | 標準ランク1。SPによる強化を基準には含めない |
| パッシブ・専用強化 | 取得しない。余剰SPは保持 |
| 装備 | 全地域の武器・防具メインをsまで取得 |
| 枝・終端・ジェム・薬 | 使用しない |

「上から全部取る」は上表の配分として明文化した。現行は1段階1SP・各技最大5段階なので、Lv.5なら最初のアクティブを5段階、Lv.10なら最初の2技を5段階ずつ取得できる。通常攻撃にSPを先に使う配分とは分ける。配分を変える際は基準係数を再計測する。

現行はメインをそのステージの**クリア後**に購入する。したがって、同じレベル・スキル・仲間で次の3条件を検証する。

1. メインsまで：ユーザー指定の取得後の基準。
2. メインs−1まで：初回攻略可能性。森1は装備ノードなし。
3. メインs−10まで：強化不足の敗北基準。s≥10で評価。

仲間は取得後の基準でも挑戦前の構成に固定する。森4に魔法使い、森10にパラディンを入れて難所を隠さない。

## 2. 火力と実効耐久を別々に20%成長させる

初期値を以下とする。20%は調整可能な仮値。

```text
ステージ倍率 r = 1.20
レベル倍率   l = 1.02
装備倍率     g = r / l = 1.176470588…

ステージ基準 P(s) = r^(s−1)
レベル寄与   L(v) = l^(v−1)
メイン寄与   G(k) = g^(k−1)    （未取得k=0も定義）

基準に対する能力比 = l^(v−s) × g^(k−s)
```

適正レベル・適正メインでは能力比1。レベルが適正で装備だけ10段階遅れると `g^(−10) ≈ 0.1969`。レベルとスキルだけで装備不足を埋めない構造になる。

ここで成長させる軸は**パーティーDPSと実効耐久EHP**。HP・防御を両方20%ずつ増やして、さらに耐久20%を掛けることはしない。火力側も攻撃力・攻撃速度・会心の積を1つの予算に収める。火力×耐久という総合値を使うなら1段階1.44倍になり、「総合値だけ20%」とは意味が異なる。

20%を一定にしても、後半のノードの絶対増分は指数的に増える。地域ごとのリセットや別倍率は不要。成長率そのものを後半で上げる必要が出た場合は `log P(s) = Σ log r_i` に変更し、以下の勝敗条件を再検証する。

`P`、`L`、`G`は説明用の記法。実装で遠いステージの巨大な累乗を生成しない。比較はステージ差の指数、表示や増分管理は対数で行う。検証ツールは10万ステージでも絶対能力値を作らない。経験値にはこの式を使わず、既存の `{level, progress}` と負の指数・閾値を維持する。

## 3. メインと追加ノードは絶対量の加算にする

メインnの増分は `G(n)−G(n−1)`。同じメイン1個でも後半ほど大きくなる。

追加ノードは、そのノードを取って進む**次のステージ**のメイン基準を参照する。

```text
追加ノードnの増分 = ε × G(n+1)
ステージsでの効果率 = ε × g^(n+1−s)
```

| ノード | εの初期値 | 予算の数え方 |
| --- | ---: | --- |
| 枝 深さ1〜4 | 1%、1.5%、2%、3% | 上下各4個、1ステージ8個／装備ツリー |
| 終端の根 | 3% | 地域10に1個 |
| 終端3方向×深さ1〜3 | 1%、2%、3% | 地域10に9個 |

ステージ9の枝を取って10へ進む場合、1個の効果は1〜3%。ステージ19の枝を取って20へ進む場合も同じ1〜3%。ステージ9の枝が20で与える効果は、その約19.7%。旧ステージの追加ノードも、取得直後の次ステージでは新しい枝と同じ効率になる。

これを現在能力への永続的な百分率乗算にすると、昔の全ノードが未来にも同じ率で効き続ける。上の式では**参照時点の固定増分を足す**ので、古いノードの相対効率が自然に下がる。取得数によるジェム容量は既存どおり残し、旧地域の回収価値を維持する。

1ノードが攻撃・速度など複数項目を持つ場合、最終DPSの増分がεに収まるように分配する。HP＋防御ならEHP、MP回復なら実測ローテーションDPSへの寄与で評価する。各項目をそれぞれ3%増やすという意味ではない。新旧の取得数ボーナスに直接の戦闘効果を残す場合も、追加ノード側の合計予算に含める。

## 4. やり込みの上積みにも予算を設ける

上の枝・終端すべての効果を各軸に加算した保守的な計算でも、無限の地域を全取得したときの上積みは有限になる。

```text
枝の1段階合計 b = 2 × (0.01+0.015+0.02+0.03) = 0.15
終端の1地域合計 c = 0.03 + 3×(0.01+0.02+0.03) = 0.21

全追加ノードの上限倍率
  = 1 + b×g/(1−1/g) + c×g/(1−g^(−10))
  ≈ 2.484
```

ジェムには各軸の**合成効果**として最大1.5倍を仮の予算とする。容量が増えても即座に上限へ達しないよう、投資量xの変換を `1+0.5×x/(1+x)` とする。これは今の個々のジェム値を変更した仕様ではなく、次の実装で必要な上限設計案。

追加ノードとジェムの合成上限は約3.726倍。20ステージ遅れは `g^(−20) ≈ 0.03876` なので、全取得の上限を乗せても各軸は約14.4%になる。森10だけの全取得＋ジェム上限で森10から20先に挑むなら約12.7%。解析モデルではいずれも敗北。

ただし、この上限は**同じ対象に対する最終DPS・最終EHP**に掛ける予算。無制限の範囲増加、永続拘束、重複軽減、回復による無限生存は別の突破経路になる。範囲や回復も密集・単体・耐久試験で予算へ換算する。容量を増やすごとに攻撃・速度・会心へ別々に1.5倍を掛けない。

「10段階遅れならクリア不可」は枝・ジェムなしの比較条件。旧ノードの全取得やジェムで数段階を緩和することは許容し、20先まで不要になることを禁止する。この2条件を区別する。

## 5. ダメージは攻撃と防御の比で決める

現行の `80/(80+防御)` は、攻撃・防御が大きくなっても80が固定なので同じ比率の攻防で軽減率が変わる。候補式は以下。

```text
A = 攻撃者の基礎攻撃力
D = 防御者の防御力
κ = 防御換算係数（初期案1）
m = 技の威力・会心・属性などの倍率

軽減後倍率 f = 1 / (1 + D/(κ×A))
ダメージ    = A × m × f
実効耐久EHP = HP / f = HP × (1 + D/(κ×A))
```

攻撃・防御を両方100倍しても軽減率は同じで、ダメージだけ100倍になる。防御を増やした分はEHPへ滑らかに寄与し、攻撃−防御方式の閾値や多段ヒットの極端な無力化を避けられる。

**mを防御計算のAに含めない。** 同じ攻撃力なら多段・単発で同じ軽減率にする。技の大きな倍率で防御まで突破すると、スキル間の比較軸が増える。防御貫通は明示的な効果として別予算にする。

鎧のメイン成長はEHPを目標にする。防御Dを先に決める場合は `HP = 目標EHP / (1+D/(κ×敵基礎攻撃力))` からHPを戻す。敵の代表攻撃力を固定して初期値を生成し、個々の攻撃者には上記の同じダメージ式を使用する。

通常の戦闘計算はこの四則演算で足りる。長期の数値生成・比較には対数が必要になる。検証ツールでは `D/A/κ` の順に除算して和・積のオーバーフローを避け、1e308同士の攻防も検査する。本編で巨大数まで対応する際はHP・攻防を同じ指数で正規化するか、仮数＋指数で持つ。ツールは本編の巨大数保存まで実装したものではない。

## 6. 仲間とスキルの非連続成長は実測係数で補正する

ステージsの基準ビルドを使い、攻撃力・会心・装備の影響を除いたローテーション係数を `C_D(s)` とする。単体ボスと密集雑魚で係数を分ける。

```text
基準パーティーDPS(s) = 基礎係数 × P(s) × C_D(s)
敵のHP予算(s)        = 基準DPS(s) × 目標討伐時間
敵HPの前段階比       = r × C_D(s)/C_D(s−1)
```

敵の数を増やすステージでは1体あたりを同じ倍率で増やさず、**全編成のHP予算**を雑魚・ボス・ウェーブへ配分する。敵が防御を持つ場合はHPの代わりに敵EHPで予算を扱う。スキル解放、範囲の拡大、仲間加入による火力の跳ね上がりをここで吸収できる。

`audit:balance` は現行AIを攻撃力1000・会心なしの不死標的で180秒動かし、後半120秒を計測する。MP不足、技の競合、動作時間、移動を含み、単に全スキルの威力／CDを足さない。単体標的と5体密集標的の2条件をJSONに記録する。

基準係数はステージデータ生成時に固定する。実際のプレイヤーが枝・ジェムを付けるたびに敵を強化しない。

キャラごとの基礎攻撃力を変える場合は、JSONのキャラ別寄与にその攻撃係数を掛けてから合算する。標的試験の表は全員の攻撃力を1000に揃えた係数であり、そのまま現行の異なる攻撃力の合計DPSを表した値ではない。

防御側の補正 `C_E(s)` は、無被弾標的では測れない。実装時には固定の単体・範囲・継続ダメージの圧力を与え、タンクへの集中率、回復、軽減、挑発、拘束を含む生存時間を測って求める。仲間が増えたから敵攻撃力を人数倍する、あるいは全員のHPをそのまま足す、という補正はしない。

集中被弾率p_iが既知で回復を含めないなら、最初の戦線崩壊までの耐久は `min(EHP_i/p_i)` で見積もれる。生存者が減ると火力も低下するため、その後は実戦シミュレーションで判定する。長期戦で無限回復にならないことも確認する。

## 7. 長期戦で勝てる敵HP・火力を逆算する

基準ビルドの初期値は討伐60秒・生存85秒とする。

```text
敵HP予算        = 基準パーティーDPS × 60秒
敵の実効DPS予算 = 基準実効耐久 / 85秒

攻撃能力比a、耐久能力比eの挑戦では
必要討伐時間 = 60/a
生存時間     = 85×e
勝利条件     = a×e > 60/85
```

| 条件 | 各軸の能力比 | 必要討伐時間 | 生存時間 | 解析結果 |
| --- | ---: | ---: | ---: | --- |
| 適正メイン | 100% | 60秒 | 85秒 | 残HP約29.4%で勝利 |
| 前ステージまで | 85% | 約70.6秒 | 約72.3秒 | 残HP約2.3%で初回勝利 |
| 10段階遅れ | 約19.7% | 約304.8秒 | 約16.7秒 | 敗北 |
| 20段階遅れ＋全上積みの理論上限 | 約14.4% | 約415.4秒 | 約12.3秒 | 敗北 |

85秒には初回攻略を成立させる意味がある。前ステージまでのメインで勝つには `生存時間 > 60×g² ≈ 83.0秒` が必要で、75秒では初回基準を満たせない。初回の余裕2.3%は小さいので、実戦で配置による敗北が出る場合は生存目標を増やすか、初回用の敵HPを下げる。

一定の敵DPSを最後まで受ける解析モデルは、実際の敵数の減少やタンク死亡を再現しない。60秒を全ウェーブの攻撃時間予算として配分した後、演出待ちや移動を含む最終のクリア時間を確認する。回復がある場合は回復後の純被ダメージで生存時間を測る。敵の大技1発は前衛最大HPの20〜30%程度を仮の上限とし、平均DPSだけで即死を見逃さない。

## 8. スキルは便利さと動作損失を含む共通予算で作る

初期の正味火力予算は、解放Lv.uに対して `Q(u)=0.6×(1+0.03×max(0,u−5))`（基礎攻撃力／秒）とする。同ランク・同じ性質なら後の技ほど増加する。

| 性質 | 便利さの倍率R | 火力への影響 |
| --- | ---: | --- |
| 単体・近接 | 1 | 基準 |
| 遠距離 | ×1.10 | 威力予算÷1.10 |
| 範囲 | ×1.15 | 威力予算÷1.15 |
| 貫通・連鎖 | ×1.10 | 威力予算÷1.10 |
| 拘束・無敵など追加効果 | ×1.10〜 | 効果時間に応じて増やす |

複数の性質は掛け合わせる。無敵・致死耐性・強い拘束を一律10%で評価し切れるとは扱わず、被害回避量・作用時間を実測してRを増やす。

密集時の想定巻き込み数Nに対し `N_eff=1+0.35×(N−1)` を初期値とする。最大敵数36をそのまま使わず、通常配置での命中数を測る。対象数の多い技は総火力を増やしつつ、1体あたりの威力を引く。

```text
C = 再使用時間（秒）
t = 動作中に通常攻撃が止まる時間（秒）
d0 = 通常攻撃DPS／基礎攻撃力
h = 1体に当たる重み付きヒット数（終撃倍率を含む）

1ヒット威力 = [Q(u)×C/(R×N_eff) + d0×t] / h
正味単体DPS = [h×威力 − d0×t] / C
```

技の動作中に失った通常攻撃を戻してから、正味寄与を比較する。前半の技を削除せず、後半の長い再使用待ちの間に使う価値を残す。支援技はダメージ0でも、回復・軽減・中断による実効耐久の予算で評価する。現在のスキル威力の変更は今回含めない。

ローテーションでは使用回数／秒をλ_iとして、以下を満たす必要がある。

```text
λ_i ≤ 1 / max(C_i, t_i)
Σ λ_i×t_i ≤ 1
Σ λ_i×MP_i ≤ MP回復/秒 + 初期MP/計測時間
合計DPS = d0×(1−Σ λ_i×t_i) + Σ λ_i×h_i×威力_i
```

「後半ほど高い」は同じランクで安全性・範囲を揃えた正味寄与で確認し、単体の実測DPSにも逆転がないかを併せて確認する。新技ランク1と旧技ランク5の比較は別条件。スキルごとの単発係数だけでなく、新しい技を加えた際にAIの技選択やMP不足で全体DPSが下がらないことを計測する。

ジェム・スキルのゲーム内ツールチップには、この設計解説を追加しない。表示は既存方針どおり効果名・数値・パラメータのみ。

## 9. 検証と本編へ適用する順序

```sh
npm run test:balance-model
npm run audit:balance
# 式だけを素早く検証
npm run audit:balance -- --formula-only --out=output/balance-formula
# 同じ条件を30配置で実測
npm run audit:balance -- --seeds=30
# 別の仮設定を試す
npm run audit:balance -- --config=tools/balance/balance-model-config.json
```

設定は [balance-model-config.json](../../tools/balance/balance-model-config.json)。計算モジュールは [balance-model.cjs](../../tools/balance/balance-model.cjs)、現行戦闘の計測は [audit-balance.cjs](../../tools/balance/audit-balance.cjs)。標準出力先は [検証表](../../output/balance/audit.md) と [全計測JSON](../../output/balance/audit.json)。新しいスクリプトは本編から読み込まない。

解析条件に違反する仮設定では検証ツールが終了コード1を返す。現行ゲームの敗北や時間切れは診断結果として記録し、提案式の失敗と混同しない。

1. 基準ビルド、20%の意味、SP配分を固定する。
2. 基準DPS・耐久を計測し、仲間・スキル解放の係数を作る。
3. メイン・枝・終端を共通の加算式へ置き換える。
4. 敵編成へHP予算・火力予算を配り、同じ攻防比のダメージ式へ移す。
5. 実戦シミュレーションでHP倍率と火力倍率を探索する。まず適正メイン勝率・討伐時間を合わせ、次に残HPを合わせる。単発被害と初回攻略も確認する。
6. 同じ調整値で10段階遅れ・旧地域全取得＋20先・単体／密集・ボス／雑魚・MP切れを再検証する。

共通式全体の評価目標は、各ステージ30配置以上で適正メイン勝率95%以上・討伐中央値45〜90秒・初回勝率90%以上、10段階遅れ勝率5%以下、旧地域全取得＋ジェムの予算上限で20先の勝率5%以下。集約モデルの残HP15〜35%をパーティー合計HPへ直接適用すると、前衛の死亡を前提にした調整になりやすい。実戦では前衛残HP25%を探索の目安とし、適正メインで全員生存90%以上も確認する。召喚・形態変化・回復・無敵を含む実際の戦闘を最大180秒動かし、時間切れも失敗とする。

敵のみを調整した今回の合格条件と実績は [stage-balance-adjustment.md](../history/stage-balance-adjustment.md) に記録。20先への過剰強化防止、装備1ノードの1〜3%予算、スキル間のリスク補正は共通式全体を適用する時の課題として残る。

## 10. 調整前とのずれ（初回実測）

以下は敵編成・数値を変更する前の40ステージ×3条件×5配置の記録。`npm run audit:balance` は実行時の本編データを測定するため、再生成後の表とは区別する。

- 適正メインは195/200勝利。森3が5/5敗北。森4の初回基準は2/5勝利。
