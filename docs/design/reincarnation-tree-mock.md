# 転生ツリーのレビュー用モック

2026-10-18、レビュー第2版。**見た目・内容を確認する未採用案。本編への転生処理・保存・戦闘効果は未接続。** [転生企画の第6節](reincarnation-system-design.md#6-転生ツリー)を土台にする。成果は作業ブランチで確認後、ユーザー指示に従い `dev` へ集約する。

## 確認方法

作業ワークツリーで `PORT` を未使用の番号に設定して `npm start` を実行し、`/development/labs/reincarnation-tree.html` を開く。[検証画面の入口](../../development/labs/index.html)からも移動できる。

- 星図：ノードを選ぶと右側に効果・合計の変化・すべての前提・価格を表示。前提名を選ぶと該当ノードへ移動。ホバーでも効果・状態・前提を確認できる。
- 取得：確認画面で確定した場合だけモック内で消費する。前提未達・残高不足・重複取得は不可。払い戻しは設けない。
- レビュー状態：初転生、主目標直前、高速周回、試練攻略50,000 PT、深層試練2,000,000 PT、全取得を切替。追加100 PTと「状態を戻す」はレビュー用。切替・再読込で試行内容は失われる。本編の保存データは読み書きしない。
- 系統：8系統の選択で該当枝を強調。名前・効果で検索。ノード一覧では絞り込んだ全件の効果・価格・状態を比較できる。
- 表示：空白をドラッグまたはスクロールで移動、拡大・縮小・全体・100%で調整。通常幅・狭い幅に対応。ノード上ではドラッグを開始しない。キャンセル・キャプチャ喪失で操作状態を解除する。

## 構成と内容

起点を除く54ノード。序盤→主目標→8系統の枝という上から下への構成。ドロップ率と大ボス素材はそれぞれ独立した列に展開。初期価格8件は企画書の仮価格を維持し、後半46件の価格・効果・前提はレビュー用追加案。一覧の `*` と詳細欄で区別する。すべての価格は未採用。

| 段階 | 内容 |
| --- | --- |
| 初転生 | 100 PT。ドロップ数2倍60、経験値3倍20、ゴールド2倍20で使い切れる |
| 主目標 | 経験値3倍・通常サブ素材費20%軽減・通常ユニーク素材費20%軽減から、メイン材料無償化400へ接続。通常10地域・全職・武器／防具のメイン素材のみ0、ゴールド・到達条件は維持 |
| 収穫 | 抽選後個数を2→3→4→6→10→20→100倍。ドロップ率は別枝の7段階で合計＋100→250→500→1,000→3,000→10,000→30,000%。ジェム制限中も有効。ゴールド倍率は別枠 |
| 成長 | 経験値指数＋1の積み重ねで3→9→27倍。Lv.100以降は無効 |
| 再走 | サブ・ユニークの費用軽減、装備ゴールド費軽減、進行幅＋2→＋3→＋4。ボスを越えず、通過区間の報酬なし |
| 火力 | 与ダメージ＋25%→×2→対ボス＋50%→×3→×10。共通与ダメージは最終75倍、対ボスはさらに別補正 |
| 耐久 | 最大HP＋25%→×2→回復量＋50%→HP×3→×10。最大HPは最終75倍 |
| 技能 | レベル由来SP＋20%、10LvごとSP＋1、MP消費−20%、技能威力＋50% |
| 宝石・容量 | 共通＋50、各方向＋100、共通＋200。別枝で大ボス素材費75%→50%→25%→0。星界の残滓を含み、欠片の必要数は維持。地域Lv強化の結晶は対象外。職専用容量は別 |
| 試練・異変 | メイン無償化＋ドロップ数4倍から試練の扉。敵側強化→宝石封印・技能制限→同時枠2→追加敵→少人数上位試練。追加敵に火力・耐久、少人数に容量・技能の前提を設ける |

主目標まで最短の初期投資例は合計560 PT（6回相当）。途中でドロップ数3・4倍も取得すると760 PT（8回相当）。通常転生100 PT/回は価格比較用であり、所要時間の検証値ではない。主目標直前プリセットは600獲得・160投資・440残、取得後は40残。

「試練の扉」は試練回数から解放せずノード購入で解放。基本自動化・設定変更・保護・振り直しなどを有料ノードに含めない。今回、隠しボス発見前の本編導線には接続しない。

後半は10,000→100,000→1,000,000 PTの価格帯を設ける。例：試練同時枠10,000、追加敵100,000、少人数上位試練1,000,000 PT。火力・HP・個数・ドロップ率にも100万PTの節目を置く。大ボス素材の4段階は400→4,000→40,000→400,000 PT。通常100 PT換算の周回数は価格比較の表示であり、試練での収入増加を含む実際の所要時間ではない。

大ボス素材30個の制作例は30→23→15→8→0個。欠片100個の例は常に100個。詳細欄で現在→取得後を確認できる。制作→解体による資源循環の確認は本編接続時に行い、今回の効果はモック内だけに適用する。

## 実装と検証

- 転生用画面・データは `development/labs/` 内に配置。本編の既存アイコンを再利用し、新規素材や戦闘エフェクトは追加しない。
- 共通の空白ドラッグは `public/js/ui/tree-navigation.js` と `public/css/tree-navigation.css`。本編のスキル・通常装備・女神装備とモックから利用する。本編は開発コードを読み込まない。今後もすべてのツリーUIで共通にする方針を `AGENTS.md` に記載。
- データ：前提の欠落・循環、プリセットの予算と前提、取得可否・重複取得、560/760 PT、整数ドロップ数、倍率集計を `node --test tests/reincarnation-tree-mock.test.cjs` で確認。
- ブラウザ：`FOREST_TEST_URL` に起動先を指定し、`node tools/verify/verify-reincarnation-tree-mock.cjs`。通常幅・狭い幅、購入確認の取消・確定、状態切替・検索・一覧・倍率・ズーム、再読込と本編セーブの非変更、実行エラー・欠落リソースを確認する。画像は `output/reincarnation-tree-mock/`。
- 共通操作の回帰：`node tools/verify/verify-gear-navigation-ui.cjs` で通常装備・女神装備・スキル、両軸ドラッグ、ホイール、ノード選択・購入後の保持、キャンセル・キャプチャ喪失、複数画面幅を確認。
- 構造：`npm run check:structure` と `node --test tests/repository-structure.test.cjs`。

バランス数値の採用、実戦の所要時間、転生の原子的な保存、試練・スキップ・制作費軽減の資源循環は本編実装時の検証対象。モックのノード取得は効果表示だけを変える。
