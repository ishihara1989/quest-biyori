# 輪廻の絆・封印の試練の解放ノード

2026-10-22 JST。本編実装。ユーザーの範囲指定に従い、個別の封印・ソロ試練は今回追加しない。[設計・バランス案](../design/sealed-trials-and-progression.md)に名前候補・報酬の定義案・現行戦闘の測定と未決定事項を記載。

| ノード | 費用 | 前提 | 今回の動作 |
| --- | ---: | --- | --- |
| 輪廻の絆 | 4,000 PT | メイン材料無償化 | 全6職が最初から同行 |
| 封印の試練 | 4,000 PT | 試練の扉・闘志5・生命5・輪廻の絆すべて | 取得・保存が可能。個別試練は設計中と表示 |

闘志5・生命5は各7.5倍の5番目ノード。保存互換用ID `damage2`・`hp2`を使う。未実装の「重なる試練」以降は従来どおりComing soon。

## 全員同行

「輪廻の絆」は購入直後からキャラの操作・育成・次の戦闘の編成に反映する。他の転生強化と同じく進行中の戦闘の開始時スナップショットは維持する。既に育てたキャラのレベル・装備・スキルを購入時に初期化しない。

転生または試練から新しい周回を始めると、全6職ともLv.1・装備ツリー未取得・スキル未取得で森1から同行する。途中加入時のLv.20〜40、メイン装備、巫女・呪術師の取得スキルを前倒し支給しない。レベル由来のSP・通常攻撃は既存ルール。

全員が通常の経験値を得て、育成・自動取得・ジェム装備の対象になる。ただし地域・ステージ・装備ツリーの到達条件は別なので、仲間加入だけで先の地域の装備を取得できない。

保存読込でもLv.1を維持し、従来の魔法使いの最低加入Lv.4や忍者・呪術師・巫女の加入支給を適用しない。本来の加入ステージやスキップ区間を通過してもレベルを上書きせず、加入演出を再生しない。未取得時の従来の加入・保存復元ルールは維持する。

転生と試練開始の確認画面も、取得済みなら最初から全員同行すると表示する。購入ノードは既存の保存形式v3の取得IDへ含め、PT・前提・重複取得の検証を共通処理で行う。保存形式の変更はない。

## 確認方法

作業用の専用ポートで `/development/labs/reincarnation-system.html` を開き、「輪廻の絆・封印の試練」を選ぶ。闘志5・生命5・扉は取得済み、合計20,000 PTの状態になる。

転生ツリーで封印の前提4個と購入不可を確認→輪廻の絆を4,000 PTで購入→封印を4,000 PTで購入→再読込→スキル画面の6職→試練タブから新しい周回を開始→全員Lv.1で森1の戦闘。封印ノードの注意書きどおり、個別の封印系試練はまだ増えない。

## 検証

`tests/cycle-bond.test.cjs` は価格・前提・PT不足・重複取得・保存・再読込・次周・6職編成・全員の経験値・加入報酬の非再適用・先の装備の復元拒否・通常加入の維持を確認する。`npm run test:reincarnation` に追加。

`npm run check:seals-ui` は1440px／390pxの購入条件、確認取消、購入、保存・再読込、6職の選択、新周回のLv.1、初戦の5人の仲間を確認する。

戦闘数値の調整はなし。転生・試練・成長・報酬・通常戦闘・キャッシュの接続を対象テストで回帰確認する。文書・ツールの追加は `npm run check:structure` で確認する。現行女神戦の基準測定は設計案へ記載し、試練の正式な合格結果とは分ける。

検証結果：新規5件を含む対象130件が合格。転生・試練・保存・通常加入・自動装備・通常戦闘・女神同時戦・ゲート解放・洞窟／海岸／遺跡の接続を確認した。1440px／390pxの新ノードUI操作と構造検査も合格。画面検証中は専用の一時ポートと確認用セーブだけを使用した。
