# テストと動作確認の方針

2026-10-13制定。プロジェクト全体の変更に適用する採用済みの共通方針。

## 基本原則

変更で壊れ得る範囲を確認し、必要な確認が合格したら終了する。検証の範囲と実行時期を調整し、[バランス方針](balance-policy.md)・[素材制作と検収](../../AGENTS.md)の合格基準は維持する。

- 検証対象は変更ファイルの名前だけで決めず、変更した振る舞い・利用元・接続部分から選ぶ。共通ファイルに地域定義を追加しただけの場合と、全地域で使う処理を変更した場合を区別する。
- 既存の対象テストを優先する。新しい振る舞いや不具合修正で既存テストに不足がある場合は、失敗条件を再現するテストを追加する。文言・色などの軽微な変更に、実装をなぞるだけのテストを追加しない。
- 作業途中の早い確認と、完成時の正式な確認を分ける。同じ結果を自動テスト・監査・報告書で重複計算しない。
- 検証を広げる場合は、追加で確認する故障条件と対象を明確にする。影響範囲が不明な場合は利用元を調べ、未解決の懸念に対応する確認を追加する。

## 変更別の確認範囲

| 変更内容 | 必要な確認 |
| --- | --- |
| 文書のみ | 追加・配置・リンク変更時は `npm run check:structure`。ゲームの戦闘・ブラウザ検証は不要 |
| 文言・色・配置 | 該当画面を確認。レイアウト変更なら通常幅と狭い幅。操作や状態表示も変更した場合は、その操作・状態を確認 |
| 画像・モーション | 新規・変更素材の登録、透過、見切れ、位置・色調、全コマ、連続再生と本編表示。四足歩行は [標準制作・検収手順](quadruped-trot-production.md)を適用 |
| ステージ編成・敵HP・火力 | 定義・ウェーブ・敵の参照・報酬などの整合性と、影響するステージのバランス |
| ドロップ・装備費用 | 抽選境界・確定分と端数・期待報酬・素材予算など、変更した規則を確認。戦闘能力を変更していなければ戦闘バランスの再計算は不要 |
| 新しい敵行動・状態異常 | 発動前後、命中・範囲境界、中断、解除、重複、戦闘終了・ウェーブ切り替え時の清掃を対象テストで確認。本編では予告・モーション・演出と判定の対応を確認 |
| 共通戦闘処理・成長式・保存仕様 | 利用する既存機能へ回帰確認を広げる。全地域の難度に作用する変更は全地域のバランスを確認。保存変更は新規状態と、維持対象の保存データの読込・再保存を確認 |
| モジュール・アセットの移動 | [配置基準](repository-structure.md)に従い、`npm run check:structure`・関連テスト・`npm test`を実行 |

追加・構造変更時の `check:structure` は [AGENTS.md](../../AGENTS.md) と配置基準に従う。共通描画・再生・素材加工処理を変更した場合は、変更素材だけでなく、その処理を利用する既存素材にも確認を広げる。

## ステージ・地域追加

### 作業途中

- 新地域の対象ロジックテストと、変更ステージの固定3配置程度で確認する。少数配置は問題を早く発見するために使い、完成時の30配置検証の代わりにしない。
- 少数配置でも、適正・前ステージ装備の敗北、時間切れ、被害上限超過などを検出する。測定値を出力するだけのコマンドを合否検証として扱わない。
- 新しい行動の中断・状態解除などは、長い実戦を待たず、対象の状態・時刻を用意するテストで確認する。

### 接続部分

- 前地域最終ステージのクリアによる解放と、新地域入口への自動進行。
- 新最終ステージでの同一ステージ周回、敗北時の戻り先と周回設定、OFF時の停止。
- 素材・ジェム・装備ツリーなどの登録と、前地域からの装備接続。
- 新規状態および維持対象の既存保存データの読込・再保存、新地域の進行・所持品・育成の保持。
- 本編の地域選択・装備画面・戦闘開始、読み込みと実行エラー、変更画面の通常幅と狭い幅。

### 完成時

- 新地域全ステージの適正・前ステージ装備を各30配置で検証する。洞窟以降の大ボスは装備主道5段階遅れも30配置で確認する。全勝、5段階遅れの勝利3/30以下、最大単発被害51%以下などの判定と、時間の目安はバランス方針に従う。
- 全員生存率・通常難所の装備10段階遅れなど、バランス方針で参考測定とされる項目は毎回の必須確認にしない。
- 新規・変更素材は必要な全コマと連続再生を検収し、本編で新しい行動と表示を確認する。検収後の数値調整では、素材や描画・再生への影響がなければ素材検収を繰り返さない。
- 新地域専用処理の追加だけなら、既存全地域の30配置検証は毎回の対象にしない。共通処理も変更した場合は、その利用元に回帰確認を追加する。
- 完成後に一部ステージを修正した場合は、影響するステージ・行動・接続部分を再確認する。共有敵・能力式の変更は、その敵や式を使うステージへ範囲を広げる。

## 実行結果の再利用と終了条件

- 成功済みの結果は、対象コード・依存処理・素材・テスト入力・検証条件が変わらない範囲で再利用する。古い報告書が存在するだけでは、現在の変更が合格した根拠にしない。
- 同じステージ・装備・配置・条件の戦闘結果から、合否判定と報告書を作る。報告書を生成するためだけに同じ戦闘を再計算しない。
- 選んだ確認がすべて合格し、新しい変更・失敗・未解決の懸念がなければ検証を終了する。時間に余裕があることを理由に、全テスト・全画面確認を追加しない。
- 失敗した場合は原因を直し、その修正で影響する確認を再実行する。合格済みの無関係な確認は繰り返さない。
- 完了報告には確認した範囲と結果を簡潔に記す。必須確認が未実施・未合格なら、その理由と残っている確認を明示する。

## 検証コマンドの扱い

この方針の制定時点では、既存のnpmコマンドや検証ツールの動作は変更していない。`npm test`には長時間のバランス検証が含まれるため、毎回の変更で自動的に全実行せず、上記の影響範囲と必須条件から選ぶ。

検証ツールを追加・修正する際は、通常テストと長時間のバランス監査、ブラウザの基本動作確認と素材の全コマ検収をそれぞれ独立して実行できるようにする。対象地域・ステージ・素材を指定できるようにし、少数配置の測定と正式な合否判定を区別する。
